# План резервного копирования

Локальный веб-справочник планов резервного копирования для нескольких обслуживаемых организаций.
Приложение **только документирует** планы и ничего не копирует: что, откуда, куда, как часто и чем копируется.

## Модель данных

```
Хранилища (общий справочник)    NAS, SMB, USB, S3, Яндекс.Диск…; scope: local | remote
  └── org_ids                   каким организациям хранилище доступно

Организация (название, #тег, цвет аватара)
 └── Устройство                 сервер / ВМ / ПК: имя, IP, ОС, роль, расположение
      └── Набор                 что копируем: папка, файлы, база 1С, общая папка, образ…
           └── Копии 1..N       хранилище, from (source | id другой копии), stage (статус),
                                инструмент, расписание, хранение

Справочники (data/dictionaries.json)  set_types, storage_types, device_kinds — значения с кодом и значком (icon);
                                      tools, os, roles, hypervisors, locations — подсказки (datalist)
```

## Правила

- В копии можно выбрать только хранилище, доступное организации.
- Хранилище, созданное из организации или из формы набора, сразу получает доступ этой организации.
- Снять доступ или удалить хранилище нельзя, пока его используют копии (ответ 409 со списком копий).
- Копия берётся с источника или с другой копии того же набора, циклы запрещены.
- Статус копии `stage`: `approval` (согласование), `planned` (в плане), `active` (действует); без поля — действует.
- «Требует внимания»: у набора нет **действующих** копий или нет действующей копии на удалённом (`remote`) хранилище.
- Расписание и хранение: текст в `schedule` / `retention` (его видно в плане) + структура `schedule_spec` / `retention_spec`
  для интерактивного редактора. Текст генерирует клиент; текст без структуры разбирается при открытии, иначе «свой текст».
- Значение справочника с кодом нельзя удалить, пока оно используется (409). Размещение хранилища и статус копии — системные, не редактируются.
- Пароли не храним: в заметках указываем только, где они лежат.
- Значок значения справочника — имя из набора `ICONS` в `app.js`; пустое поле — стандартный значок по коду.
  Цвет аватара организации — код из `ORG_COLORS`; пустое поле — цвет вычисляется из тега. Чужие значения сервер сбрасывает.

## Стек и файлы

- Python 3 + Flask, без БД. Данные лежат в `data/data.json` (атомарная запись, перед каждым изменением копия в `data/backups/`, хранятся последние 50).
- Справочники — `data/dictionaries.json` (создаётся при первом изменении); стандартные значения в `dictionaries_default.json`, недостающие справочники берутся оттуда.
- `app.py` — REST API и проверки, `store.py` — чтение и запись JSON.
- `static/` — SPA на чистом JS без сборки и CDN, работает офлайн, интерфейс на русском.
- Редактирование без боковой панели: форма раскрывается под выбранной строкой (набор, устройство, шапка организации,
  строка хранилища, карточка справочника). Одна форма за раз; шапка раскрытого набора (цепочка, статус) меняется на лету.
  Форма с правками не теряется при уходе со страницы — тост предлагает вернуться. Новая организация — `#new`.
- Клик по хранилищу в цепочке или в чипе открывает карточку-подсказку; «Изменить» ведёт в `#storages/<id>`.
- Цвета: синий — действие и редактируемое, фиолетовый — удалённое хранилище, тёплый серый — локальное, статусы — зелёный/янтарный/красный.
- `demo_data.json` копируется в `data/data.json` при первом запуске.
- Запуск: `run.bat` или `.venv\Scripts\python app.py`, адрес http://127.0.0.1:8765. Превью настроено в `.claude/launch.json` (конфигурация `backup-plan`).
- Тесты API: `.venv\Scripts\python -m unittest discover -s tests`.
- После ручной проверки в браузере удалять `data/`, чтобы не оставлять тестовые правки.
