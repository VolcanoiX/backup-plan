# План резервного копирования

Локальный веб-справочник, в котором описано, **что, откуда, куда, как часто и чем** копируется в каждой организации.
Само копирование приложение не выполняет, это только документация.

## Запуск

Дважды щёлкните `run.bat`. При первом запуске он создаст `.venv` и установит Flask, затем откроет http://127.0.0.1:8765.

Вручную:

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python app.py
```

### Linux (Docker Compose)

Нужны Docker и плагин Compose v2. В корне проекта:

```bash
mkdir -p data
```

```bash
UID=$(id -u) GID=$(id -g) docker compose up -d --build
```

Приложение откроется на http://127.0.0.1:8765. Данные лежат в `./data` рядом с проектом (при первом запуске туда копируются демо-данные), поэтому переживают пересборку и обновление контейнера.

```bash
docker compose logs -f      # логи
docker compose down         # остановить
git pull && UID=$(id -u) GID=$(id -g) docker compose up -d --build   # обновить
```

По умолчанию порт открыт только на `127.0.0.1`. Чтобы открыть его в сети, замените в `docker-compose.yml` `"127.0.0.1:8765:8765"` на `"8765:8765"`. В приложении нет авторизации, поэтому ограничьте доступ файрволом, VPN или reverse-proxy с паролем.

## Структура

```
Хранилища (общий справочник)  — NAS, S3, Яндекс.Диск…; у каждого список организаций с доступом
Организация (название, #тег, цвет аватара)
 └── Устройство (сервер, ПК, NAS)
      └── Набор (папка / файлы / база 1С / общая папка / образ…)
           └── Копии 1..N — хранилище, откуда (источник или другая копия), статус,
                            инструмент, расписание, хранение
```

- Из карточки организации хранилище можно создать сразу: оно попадёт в общий справочник с доступом этой организации.
- Снять доступ к хранилищу или удалить его нельзя, пока на нём лежат копии.
- У каждой копии статус: «согласование», «в плане» или «действует». Защитой считаются только действующие копии.
- Наборы без действующих копий или без действующей удалённой (offsite) копии отмечаются как «требует внимания».
- Расписание и хранение задаются в интерактивных формах (дни недели и время, интервал, ежемесячно, срок, количество, GFS…)
  или свободным текстом.
- Раздел «Справочники»: типы наборов, хранилищ и устройств, подсказки для инструментов, ОС, ролей, гипервизоров, расположений.
- Форма редактирования раскрывается прямо под выбранной строкой. Пока правите набор, его цепочка копий и статус
  в шапке формы меняются на лету. Esc или «Отмена» сворачивают форму.
- Клик по хранилищу в цепочке показывает его карточку: адрес, заметки, какие копии организации на нём лежат.
- У типов устройств, наборов и хранилищ есть значки, их можно сменить в «Справочниках».
  У организаций — цветные аватары с буквами тега, цвет можно выбрать в форме организации.

## Данные

- `data/data.json` — все данные. Читается и правится как обычный JSON.
- `data/dictionaries.json` — изменённые справочники (появляется после первого изменения; стандартные значения в `dictionaries_default.json`).
- `data/backups/` — автоматическая копия `data.json` перед каждым изменением (хранятся последние 50).
- `demo_data.json` — демо-данные; копируются в `data/data.json` при первом запуске, если его нет.
  Чтобы начать с чистого листа, удалите демо-организации и демо-хранилища в интерфейсе.

**Не храните в заметках пароли.** Указывайте, где они лежат (например, KeePass).

Переменные окружения: `BACKUP_PLAN_DATA` (путь к data.json), `BACKUP_PLAN_HOST`, `BACKUP_PLAN_PORT`.
