# Задача: редизайн веб-интерфейса

> Позже боковую панель заменили формой, которая раскрывается под выбранной строкой; актуальное поведение описано в `CLAUDE.md`.

## Контекст

Приложение уже работает: сервер на Flask плюс SPA на чистом JS, данные хранятся в JSON. Общая суть проекта описана в `CLAUDE.md`.
Текущий интерфейс выглядит шаблонно и плохо показывает суть плана: чтобы понять, **что, куда и как копируется**, приходится ходить по уровням дерева.

**Цель:** переработать интерфейс по заданию ниже. Для визуальной части использовать скилл **frontend-design**.

## Что не трогаем

- Сервер (`app.py`, `store.py`), REST API и формат `data/data.json`.
- Бизнес-правила остаются как есть:
  - хранилище доступно только отмеченным организациям;
  - нельзя снять доступ или удалить хранилище, пока его используют копии;
  - копия берётся с источника или с другой копии, циклы запрещены.
- Без сборки и фреймворков: остаются `static/index.html`, `static/style.css` и `static/app.js`. Внешние CDN не подключаем, приложение должно работать офлайн. Шрифты берём системные или кладём локально в `static/`.
- Весь интерфейс на русском языке.

Если для удобства интерфейса API чего-то не хватает, сервер можно расширить, но только **добавлением** эндпоинтов, не ломая существующие.

## Дизайн-направление

**Стиль:** современный SaaS, монохромный (ориентиры — Notion, Vercel, Linear).
- Нейтральная чёрно-белая или серая палитра. Цвет используется **только для статусов**:
  - зелёный — у набора есть локальная и удалённая копии;
  - янтарный — нет удалённой (offsite) копии;
  - красный — нет копий вообще.
- Много воздуха, аккуратная типографика, мягкие границы, тонкие разделители, сдержанные микроанимации.
- Пути, адреса, IP и теги набраны моноширинным шрифтом.

**Тема:** по умолчанию следует системной (`prefers-color-scheme`), плюс переключатель «Системная / Светлая / Тёмная». Выбор сохраняется в `localStorage` (в `try/catch`).

## Структура экранов

### Левая колонка: навигация
- Пункты **«Обзор»** и **«Хранилища»**.
- Ниже компактный **список организаций**: название, тег, точка статуса (худший статус среди наборов организации).
- Над списком кнопка «+ Организация» и поиск.
- **Дерева «организация → устройство → набор» больше нет.**

### Страница организации — главный экран
Весь план организации показан **на одной странице как документ**, без отдельных страниц устройства и набора:

```
Рога и Копыта  #RIK                         4 набора · 1 ⚠      [Изменить]

SRV-1C · Сервер 1С · 192.168.1.10 · VM / Windows Server 2019      [+ Набор]
  База 1С «Бухгалтерия»                                   ● ok
    источник ─→ NAS-01 · 23:00 · 14 дн ─→ S3 Selectel · 03:00 · 30 дн
  Образ системы                                           ▲ нет offsite
    источник ─→ NAS-01 · вс 01:00 · 4 копии

SRV-FS · Файловый сервер · 192.168.1.11                           [+ Набор]
  Общая папка                                             ● ok
    источник ─┬→ NAS-01 · 22:00 · 7 версий
              └→ Яндекс.Диск · сб 02:00 · 4 недели

[+ Устройство]

Доступные хранилища: NAS-01 · S3 Selectel · Яндекс.Диск   [+ Создать] [Подключить]
```

- Цепочку копий показать наглядно: «пилюли» хранилищ со стрелками. Ветвление (несколько копий с одного узла) должно читаться сразу. У пилюли видна пометка «локальное» или «удалённое», расписание и срок хранения.
- В шапке организации сводка: число устройств, наборов, предупреждений.
- Кнопки добавления стоят в контексте (у устройства «+ Набор», внизу «+ Устройство»).
- Клик по устройству, набору или хранилищу открывает редактирование в боковой панели.

### Обзор
Сводные цифры и список «Требует внимания» (наборы без копий или без offsite). Клик ведёт на организацию и подсвечивает нужный набор.

### Хранилища
Список хранилищ со столбцами: тип, «локальное/удалённое», адрес, каким организациям доступно, сколько копий на нём лежит. В карточке хранилища показано, что именно на нём лежит (организация → устройство → набор).

## Редактирование: боковая панель вместо модалок

- Форма выезжает **справа** (drawer), план остаётся виден слева. Закрывается по Esc, крестику и «Отмена».
- Формы: организация, устройство, набор, хранилище. В форме хранилища — галочки организаций с доступом.
- **Набор:** копии редактируются компактными строками внутри панели. Поля строки: «откуда» (источник или копия №N), хранилище, инструмент, расписание, хранение, заметки. Возле выбора хранилища кнопка «+ новое»: создаёт хранилище с доступом текущей организации и сразу подставляет его в строку.
- Удаление объекта — кнопка в панели, с подтверждением.
- Ошибки сервера (например, 409 «хранилище используется») показываются понятным текстом внутри панели.

## Что сохранить из текущего поведения

- Адрес в хеше (`#org/<id>` и т.п.): работают «Назад» и перезагрузка страницы. Для набора можно использовать `#org/<id>/set/<id>` с прокруткой и подсветкой.
- Поиск: фильтрует организации и подсвечивает совпадения (устройства, наборы, пути) на странице организации.
- Тексты подсказок и плейсхолдеров (примеры путей, подсказка не хранить пароли).
- Адаптивность: на узком экране левая колонка сворачивается, панель редактирования занимает весь экран.

## Критерии готовности

1. Открыв организацию, за несколько секунд можно понять весь её план: что копируется, куда, по какой цепочке и что требует внимания.
2. Все действия, которые были раньше, по-прежнему доступны (CRUD всех сущностей, подключение и отключение хранилищ, создание хранилища из формы набора) и работают без перезагрузки страницы.
3. Светлая и тёмная темы выглядят одинаково аккуратно, переключатель работает.
4. В консоли браузера нет ошибок, тесты проходят: `.venv\Scripts\python -m unittest discover -s tests`.
5. Интерфейс проверен в браузере на демо-данных: запуск через `.claude/launch.json` (конфигурация `backup-plan`, порт 8765).
   После проверки удалить `data/`, чтобы следующий запуск снова взял чистые `demo_data.json`.
